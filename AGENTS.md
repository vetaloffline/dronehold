# Dronehold — інструкції для агента

Проєкт: 2D-оборона бази з видобутком, вид 3/4. Godot 4.7.2, GDScript, рендерер Compatibility.
Платформи за пріоритетом: телефон → ПК → браузер.

Довідка: устрій коду — [docs/godot-notes.md](docs/godot-notes.md); концепт і ухвалені рішення —
[docs/concept.md](docs/concept.md); робота людини в редакторі — [docs/godot-editor.md](docs/godot-editor.md).

## 1. Перед першою правкою

| Задача торкається | Дія |
|---|---|
| правил гри: ціни, урон, радіуси, швидкості, хвилі, юніти, будівлі | прочитати `docs/concept.md` |
| коду в `game/` | прочитати розділ `docs/godot-notes.md` про цю частину коду |
| картинок, спрайтів, концептів | skill `art` — викликати до першої дії з картинкою |

## 2. Гілка

- Нова задача → людина набирає `/start-work <задача>`; агент сам цей skill не викликає, а робить вручну:
  `git fetch origin` → `git switch -c <тип>/<назва> origin/main`.
- Гілку створювати тільки від `origin/main`, ніколи від іншої гілки.
- Задача залежить від гілки, чий PR ще не змерджений → попросити людину змерджити цей PR; нову гілку не
  створювати, доки PR не в `main` (`gh pr view <N> --json state` = `MERGED`).

## 3. Факти й відповіді

Порядок пошуку відповіді — до першого збігу:
1. Код, доки й тести репо. Що код **робить** (рядок `file:line`), а не що обіцяє назва чи коментар.
2. Офіційна документація: docs.godotengine.org для Godot 4.7 або вихідники рушія на GitHub; дати посилання.
3. Не знайшов → написати «не знаю» або «не знайшов підтвердження» і що потрібно, щоб дізнатись. Не вигадувати.

«Працює» / «виправлено» писати тільки після перевірки (тест, запуск, замір) з виводом і exit code.
Не перевіряв → написати «не перевіряв».

## 4. Правила коду

| Умова | Дія |
|---|---|
| Будь-який код гри | тільки GDScript; C# заборонений (Godot 4 не експортує C# у веб) |
| Гарячий цикл рою `game/swarm/swarm_sim.gd` повільний | дозволено перенести на C++ (GDExtension), масиви `SwarmSim` не змінювати |
| Потрібна анімація | кодом: `Tween`, `scale`, `rotation`, синус; спрайти статичні, покадрової анімації нема. Виняток (рішення людини 2026-10-14): біг ворога з кінцівками — атлас кадрів, який скрипт збирає з частин за моделлю руху (`art/objects/enemies/lasher/lasher_run_build.py`); кадри по одному Codex не малює |
| Новий юніт | pivot спрайта біля ніг; під ним тінь-еліпс; вузол у Y-sort світу |
| Ціна будь-чого | словник `{"crystal": 50}`, не число (див. `game/core/build_catalog.tres`, `game/core/wallet.gd`) |
| Новий склад (як ядро, ретранслятор) | `add_to_group("storage", true)`; дрон знаходить його через `nearest_store()` (`game/objects/cargo_drone/cargo_drone.gd`) — другої функції пошуку не писати |
| Масові вороги | не нода на ворога: дані в масивах `SwarmSim`, малювання `MultiMesh` смугами |
| Новий об'єкт | сцена `game/objects/<назва>/` + спільний `<назва>_rig.tres`, усе `@tool`; деталі — `.claude/rules/godot-objects.md` |
| Новий об'єкт без спрайта в `art/objects/` | skill `art` до сцени: спершу спрайт, потім код |
| Новий скрипт (`.py`, `.sh`) з параметрами | `--help` / `-h`: кожен параметр з форматом і значенням за замовчуванням, приклад запуску, що пише і exit-коди; Python — `argparse` з `help=` і `epilog` (як `.claude/skills/art/scripts/sprite_check.py`) |

## 5. Обсяг і доки

- Нова механіка → спершу найменша версія, що замикає петлю «добув → збудував → вистояв»; розширення —
  окремими кроками після неї.
- Нова механіка або зміна ухваленого рішення → оновити `docs/concept.md` у тому ж коміті.

## 6. Перевірки

Коли: перед кожним комітом, що змінює `game/`, `tests/`, `project.godot`, `art/objects/` або файли `.gd`,
`.tscn`, `.tres`, `.gdshader`. Доставка з перевірками — `/ship` (набирає людина; агент сам цей skill не
викликає, а проганяє перевірки нижче вручну).

Де: редактор Godot відкритий або невідомо → тільки на копії (`.claude/rules/editor-and-perf.md`).
Редактор точно закритий → можна в репо.

```
godot --headless --path . --import
godot --headless --path . --script res://tests/run_tests.gd
godot --headless --path . --script res://tests/smoke_game.gd
godot --headless --path . --script res://tests/smoke_sandbox.gd
godot --headless --path . --script res://tests/smoke_menu.gd
godot --headless --path . --script res://tests/smoke_turret_360.gd
godot --headless --path . --script res://tests/smoke_map_editor.gd
```

Тест пройшов, якщо одночасно:
- exit 0;
- підсумковий рядок закінчується на `0 failed`: `tests:` (run_tests), `smoke:`, `sandbox:`, `menu:`,
  `turret 360:`, `map editor:`;
- у виводі нема `SCRIPT ERROR` і `Parse Error` (скрипт, що не скомпілювався, теж дає exit 0).

Headless не перевіряє шейдери й картинку → попросити людину набрати `/godot game` (агент сам цей skill не
викликає) і дати скриншот або підтвердження.
