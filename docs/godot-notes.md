# Godot: як влаштовано

Godot **4.7.2**, GDScript, рендерер **Compatibility** (OpenGL; найширше коло телефонів, доки радять
його для 2D). Платформи: мобілка → ПК → веб. Як користуватись редактором — [godot-editor.md](godot-editor.md).

## Папки

```
project.godot
game/
  ui/main_menu.tscn            головна сцена: меню (фон з дронами, кнопки, звук) — див. «Меню»
  ui/menu_theme.tres           вигляд кнопок меню: GoldButton / DarkButton (nine-slice), шрифт
  main.tscn / main.gd          гра: карта + камера + debug HUD
  sandbox/turret_sandbox.tscn  тест турелі: відкрите поле, клік — слизень
  editor/map_editor.tscn       редактор карти в грі (тільки для розробки): пензлі типів клітинок
  core/                        карта і все, що стоїть на сітці
    map_grid.gd                MapGrid: клітинки 32×24, тип клітинки (земля / прохід / скеля / плато)
    game_map.gd                GameMap: корінь сцени карти (сітка, об'єкти, гниль, поле стрілок)
    map_object.gd              MapObject: база всього на сітці (cell, footprint, прилипання)
    prop.gd / spawn_point.gd   декор, точка появи ворогів
    grid_overlay.gd            сітка і зелені/червоні рамки об'єктів у редакторі
    rot.gdshader               гниль
    map_camera.gd              камера: палець / мишка, щипок / колесо
  swarm/                       рій ворогів (див. нижче)
  objects/<назва>/             <назва>.tscn, <назва>.gd, <назва>_rig.gd (поля), <назва>_rig.tres (значення)
    core, crystal_vein, drill, machine_gun, grenade_launcher, turret (спільне пушок), slime,
    menu_drone (дрони меню: маршрут з точок)
  core/settings.gd             Settings: налаштування гравця в user://settings.cfg (звук)
  maps/map_03/                 map_03.tscn, ground/ (6 WebP-шматків землі)
  ui/debug_hud.gd              FPS, числа рою, кнопки кількості

```

Арт лежить в `art/` і не дублюється: сцени беруть PNG звідти (`res://art/...`).

## Правила

- **Об'єкт = сцена + rig.** Усі налаштування — `@export` у `<назва>_rig.gd`, значення — один спільний
  `<назва>_rig.tres`. Змінив у Inspector — змінились усі такі об'єкти.
- **`@tool` скрізь.** Анімація крутиться і в редакторі, тому параметри видно наживо.
  Вузли, створені кодом, не мають `owner` і не зберігаються у сцену.
- **Корінь об'єкта = точка на землі** (ключ Y-sort), `scale` кореня = `map_scale` з rig, діти —
  у пікселях свого PNG (`offset = −точка_на_землі`). Позиція з клітинки — `MapObject.ground_point_for()`
  (та сама формула, що в `map_03_editor.html drawObj()`).
- **Порядок шарів** (`z_index`): земля −3, гниль −2, тіні об'єктів і слизнів −1, світ (Y-sort) 0,
  ефекти пострілів +1…+10, накладка сітки 10.
- **Ефекти тільки кодом**, працюють у Compatibility: сяйва — радіальна текстура + `BLEND_MODE_ADD`,
  іскри/гільзи — власні масиви в `_draw()`. Compute-шейдерів нема.
- Текстури, які сильно зменшуються, — з `mipmaps/generate=true` у `.import` і фільтром
  `LINEAR_WITH_MIPMAPS`.

## Рій — `game/swarm/`

Ворог — це рядок у масивах, не нода (AGENTS.md). Схема розрахована на сотні тисяч; рушій рою
(`SwarmSim`) можна переписати на C++ (GDExtension), не чіпаючи решти, — масиви і є контракт.

| Файл | Що робить |
|---|---|
| `swarm_sim.gd` | `SwarmSim`: позиції, фаза, швидкість, hp, напрям, зерно; стабільні id (турель тримає id, слоти переставляються при смерті). Кожен тік: крок + розкладка по клітинках (counting sort) |
| `flow_field.gd` | `FlowField`: Dijkstra від клітинок ядра по всій карті → стрілка на клітинку. Будівлі — «дорогі» клітинки (гризуть, якщо обхід довший), скелі — непрохідні. Перераховується тільки при зміні карти |
| `swarm_view.gd` | `SwarmView`: `MultiMeshInstance2D` на кожну смугу 24 px (пів рядка) у Y-sort світі; невидимі смуги не заповнюються і не малюються |
| `swarm.gd` | `Swarm`: нода в групі `"swarm"`, параметри в Inspector, спавн, заміри |
| `objects/slime/slime_crawl.gd` | цикл повзання, порахований один раз у таблицю (256 точок) |
| `objects/slime/slime.gdshader` | спрайт + повіки й моргання на відеокарті |

**Скіни:** `art/objects/enemies/slime/slime_skins.png` — атлас, кадри по `frame_w` px поруч, у всіх
однакова точка опори й ширина тіла (будує `slime_skins.py`). Скін слизня = `seed` → `rig.skin_of()`;
у MultiMesh це `INSTANCE_CUSTOM.y` (зсув UV на кадр), тож натовп з різними скінами — так само одна
команда на смугу і правильний Y-sort. Очі в rig — по 3 на скін, у пікселях кадру; новий скін:
додати PNG у `slime_skins.py`, заміряти очі, `skin_count` + 3 очі в `slime_rig.tres`.

**Рух за тік** (на слизня — кілька звернень до масивів): стрілка своєї клітинки × крок «гусені» з
таблиці + «тиск» і «пружина». У слизня є фізичне тіло `body` = 0,8 ширини картинки: сусіди
тримаються на ширину тіла, тож картинки заходять одна на одну на 20 % — купа. Тиск — тільки понад
місткість клітинки (`cell_capacity` 0 = авто: скільки тіл влазить, ≈2,4): з переповненої клітинки в
менш повну. Пружина (`spread_strength` 40 /с) розштовхує ближчих за тіло — від решти своєї клітинки
і від центрів 4 сусідніх; злипання (`cohesion` 3 /с) підтягує до сусідів **попереду** (до 2× тіла), щоб
задні наздоганяли, а передніх ніхто не тримав. Попарних перевірок нема — 5 клітинок на слизня.
Заміри (тести `crowd`): три найближчі сусіди в тисняві ≈ 0,74 ширини (стара модель — ≈1 і більше:
розштовхувала завжди, по слизню на клітинку); 60 слизнів проходять щілину в 1 клітинку за ~60 с.
Тіло менше ~0,7 ця проста фізика не тримає: слизні западають один в одного (0,5 → 0,2–0,4 ширини).
Позиції — float32: після кроку клітинка перевіряється за збереженим значенням (інакше слизень біля
стіни округлювався в скелю й застрягав).
У скелю не заходить (перевірка клітинки, ковзання вздовж стіни). Дійшов до ядра — зникає (`reached`).

**Запити:** `nearest(pos, range)`, `damage(id, dmg)`, `damage_radius(pos, r, dmg)` — читають тільки
клітинки в радіусі.

**Повзання** — модель `slime_crawl.html` (видалений тюнер, історія git `ba44ef0`):
`f(p) = −cos(2π·u)`, `u` 0…0.5 за частку `lunge`; ціль `scale = (1 + stretch·f, 1 − squash·f)`,
пружина `k = 40 + 360·jelly`, `c = 2√k·damp`; нахил `skew = −lean·f(p − lean_phase)·напрям`; зсув
`inch·W/2·|Δscale_x| + slide·64·rate·dt`. У натовпі пружина взята зі стаціонарного циклу (таблиця при
rate 1) — для різних rate різниця мізерна. Одиночний `slime.tscn` рахує пружину кадр за кадром, як тюнер.

**Моргання в натовпі:** серія повторюється раз на `slot = серія + pause + rand` і стартує у
випадковий момент перших `rand` секунд → паузи між серіями від `pause` до `pause + 2·rand`.
Зерно слизня — `INSTANCE_CUSTOM.x` (у Compatibility 16-бітне, для зерна досить).

**Буфер MultiMesh** (12 float на слизня, перевірено по `drivers/gles3/storage/mesh_storage.cpp` 4.7):
`[x.x, y.x, 0, o.x, x.y, y.y, 0, o.y, custom×4]`.

**Заміри** (`tests/smoke_game.gd`, Mac, headless — тільки процесор, GDScript):

| Слизнів | Симуляція | Заповнення буферів (видимі) |
|---|---|---|
| 1 000 | ~1 мс | ~1 мс |
| 10 000 | ~8 мс | ~3 мс |
| 100 000 | ~76 мс | ~28 мс |

У вікні на Mac 3 000 слизнів на всій карті — ~52 FPS. Телефон не заміряно. 10 000+ на телефоні в
GDScript не потягне → наступний крок для масштабу: `SwarmSim.step()`/`bin()` і заповнення буфера на C++.

## Карта — `game/maps/map_03/map_03.tscn`

```
Map03 (GameMap)     layout = map_03_layout.png, grid (MapGrid, збережена в сцені)
  Ground            6 Sprite2D: ground_R_C.webp (z −3)
  Rot               ColorRect + rot.gdshader: шум, жилки, очищені кола (z −2)
  Shadows           тіні слизнів (z −1)
  World             Y-sort: ядро, жили, бури, пушки, декор, смуги рою
  Spawns            SpawnPoint (видно тільки в редакторі)
  Overlay           сітка, типи клітинок (скеля червона, прохід жовтий, плато синє), рамки об'єктів
  Swarm
```

- Сітка — окремий файл `game/maps/map_03/map_03_grid.tres` (`MapGrid`): `kinds` — тип кожної клітинки
  (`MapGrid.Kind`: GROUND, PASS, ROCK, PLATEAU). `can_build()` читає розміщення
  (`GameMap.placement_problem`), `blocked` (= слизні не ходять: скеля, плато) — поле стрілок і крок рою;
  `blocked` не зберігається, рахується з `kinds` при першому читанні.
- Перше заповнення — зі схеми: клітинка «Скеля», якщо скеля/прірва займає > `threshold` (0.5) — правило
  `coverage()` з `map_03_editor.html`; 156×117, скелі 4968 (тест звіряє з Python-портом; на старих
  64×48 той самий порт дає 1197, як редактор). Кнопка «Скинути сітку зі схеми» на корені карти
  заповнює заново й **стирає ручну розмітку**.
- Розміри в клітинках (32×24): турель, гранатомет, бур, точка появи 2×2; ядро, жила 6×6; слот бура —
  клітинка жили + (6, −2). Декор: `foot` з `props.json` (там ще клітинки 64×48) × 2.
- Гниль відступає від об'єктів з `get_clear_radius()` > 0 (ядро 14, бур 4 клітинки + половина
  розміру; м'який край `rot_soft` 3).
- Точка появи може стояти на скелі (старий редактор дозволяв) — рій бере найближчу досяжну клітинку.
- `tools/build_map_03.gd` збирає сцену заново: без аргументів — розстановка `demo()` старого
  редактора; з `-- шлях/map_03.json` — розстановка, збережена кнопкою «Зберегти map.json».
  Перезапис затирає правки, зроблені в Godot.

## Об'єкти

| Об'єкт | Клітинок | Що анімовано | Відомі наближення |
|---|---|---|---|
| Ядро | 3×3, ціль ворогів | падаюча й контактна тінь (Codex або силует) | розмиття тіні — зсув mip-рівня, не гаус |
| Жила | 3×3 | 3 кристалики (підйом, хитання, «оберт»), сяйва, тіні кристаликів | — |
| Бур | 1×1 | цикл опускає → заряд → постріл → охолодження → піднімає → чекає; промінь, лінза, пляма, іскри, тінь руки | без розмиття тіні руки (0,2 px на карті); у слоті жили (клітинка жили + (3, −1)) бере параметри `Drill Slot` жили і цілиться в `Hit Point` |
| Кулемет | 1×1 | поворот голови, 8 ракурсів, віддача, спалах, трасери, гільзи | тінь голови — тонована копія спрайта |
| Гранатомет | 1×1 | те саме + нахил труби (`tilt`), снаряд по дузі, вибух | тінь у режимі tilt — тільки люлька |
| Слизень | — | 2 скіни навмання, повзання, желе, нахил, моргання 1 → 3 → 2, тінь-еліпс | натовп: пружина з таблиці (див. вище) |

Пушки б'ють рій: кулемет — 1 шкоди кулею по id цілі, гранатомет — 6 у радіусі вибуху; слизень — 10 hp.

**Поворот голови (режим `snap`):** голова не обертається — показує один з 16 ракурсів. У кожного
ракурсу є азимут на землі (`view_azimuths` у rig: у кулемета заміряний на картинці, у гранатомета
рівномірний 22,5°). Ціль береться в конусі навколо азимуту ракурсу, на землі (`SwarmSim.nearest_in_cone`
з `y_squash = cam_k`): спершу поточний ракурс, далі сусідні; голова повертається на цей ракурс і
стріляє, коли він показаний. Конус за замовчуванням — половина більшої щілини до сусідів (+0,5°),
тож мертвих зон нема, турель стріляє на 360°. Заміряно на кулеметі: кут трасера до азимуту голови
≤ 15,5° (разом з розкидом куль).
Пікселі тюнера → пікселі карти: × `map_scale / tuner_scale` (кулемет ×0.345, гранатомет ×0.3).

## Меню — `game/ui/main_menu.tscn`

```
MainMenu (Control, тема menu_theme.tres)
  World (Node2D)        фон + дрони у px картинки 1672×941; масштаб і зсув рахує main_menu.gd
    Background          menu_bg.webp (фон без дронів)
    Drones/Drone1..3    MenuDrone; діти Point1, Point2 … (Marker2D) — зупинки маршруту
  Shade                 градієнт: темніше зліва під меню
  Menu/Logo, Menu/Buttons/*   кнопки; metadata `scene` (що відкрити), `turret` (з якою пушкою полігон)
  Sound (TextureButton) натиснута = звук вимкнено; Version
```

- **Фон «cover»:** `k = max(ширина / 1672, висота / 941)`, `World.position = (екран − картинка·k) · (0.7, 0.5)`
  — на вузькому чи широкому екрані обрізається край, база лишається видно. Меню відступає від виїмки
  телефона (`DisplayServer.get_display_safe_area`, лише на весь екран); на телефоні не перевірено.
- **Кнопки:** `StyleBoxTexture` малює кути nine-slice в розмірі текстури, без масштабу, тому PNG
  збережені під висоту на екрані (золота 140 px, темна 120 px; поля 99/40 і 85/34 px). Наведення —
  `modulate_color` 1.15–1.2, натиск — 0.8 і стиснення до 0.96 (tween). Шрифт — `SystemFont`
  (Avenir Next → Roboto → Segoe UI); у вебі SystemFont не працює, буде запасний шрифт Godot.
- **Дрон (`MenuDrone`):** стани сидить → злітає → летить → сідає; летить по `smoothstep` (розгін і
  гальмування), нахил від швидкості, хитання, тінь-еліпс (`_draw`), 3 сопла — `Sprite2D` з радіальним
  градієнтом і `BLEND_MODE_ADD`. Тіло й сопла — внутрішні вузли (`INTERNAL_MODE_BACK`), у сцену не
  зберігаються. Спільний вигляд — `menu_drone_rig.tres`; швидкість, пауза, фаза — у кожного дрона.
- **Звук:** вимкнено = заглушена шина `Master` (`AudioServer.set_bus_mute`), значення в
  `user://settings.cfg`. Клік кнопки — `ui_click.wav` у плеєрі на корені дерева (не обривається при
  зміні сцени). Фонової музики ще нема.

## Перевірки

```
godot --headless --path . --import                              # імпорт, exit 0
godot --headless --path . --script res://tests/run_tests.gd     # юніт: сітка, стрілки, рій, швидкість, exit 0
godot --headless --path . --script res://tests/smoke_game.gd    # гра 600 кадрів + заміри, exit 0
godot --headless --path . --script res://tests/smoke_sandbox.gd # тест турелі: кліки, обидві пушки, «стоять»
godot --headless --path . --script res://tests/smoke_menu.gd    # меню: кнопки, фон, дрон летить і сідає, звук; → тест → клік → меню
godot --headless --path . --script res://tests/smoke_turret_360.gd  # кожна турель вбиває слизня в 16 напрямах
godot --headless --path . --script res://tests/smoke_map_editor.gd  # редактор: мишка малює, прямокутник, скасування, вихід без збереження
```

Headless не компілює шейдери і не має буфера MultiMesh — картинку перевіряти запуском у вікні.
Якщо скрипт тесту не компілюється (помилка в будь-якому класі, від якого він залежить), Godot
повертає **exit 0** — тому, крім коду виходу, дивитись на рядок `tests: N passed, 0 failed` /
`smoke: 0 failed` і на відсутність `SCRIPT ERROR`.
