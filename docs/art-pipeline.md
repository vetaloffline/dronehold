# Арт-пайплайн

Як створюється арт для Dronehold: де що лежить, як генерується, як перевіряється і як потрапляє в гру.
Рішення про стиль і механіку — у [concept.md](concept.md); тут — процес.

## Структура `art/`

```
art/
  drafts/                      чернетки, НЕ в git (.gitignore: /art/drafts/)
  concept/                     апрувнуті концепти екранів (горизонтально, 16:9)
    NN_<екран>_vK.png
    prompts.md                 журнал промптів концептів
  objects/
    buildings/
      <назва>/                 одна папка на об'єкт
        <назва>.png            спрайт
        <назва>_shadow.png     тінь на землі окремим шаром
        <назва>_with_shadow.png  спрайт + тінь разом
        <назва>_*.html         HTML-тюнер (тінь, анімація) — щоб повернутись і поправити
```

**HTML-тюнери лежать поруч з апрувнутим артом** і беруть PNG із тієї ж папки за відносним шляхом
(не вшивають base64 — інакше кожен файл ~3 МБ і дублює PNG у git). Відкривати прямо з папки:
`open art/objects/buildings/<назва>/<назва>_….html`. Змінив повзунки → «Скопіювати параметри» →
скинути в чат → оновлюються PNG / `_rig.json`. Зберегти PNG зі сторінки `file://` браузер не дає,
тому результат збирається скриптом за параметрами.

Зараз є: `core/core_shadow_editor.html` (тінь ядра: тягати, масштаб, нахил; шари
`core_shadow_cast.png` + `core_shadow_contact.png`), `drill/drill_anim.html` (пози руки, час, тінь руки).

| Папка | Що там | У git |
|---|---|---|
| `art/drafts/` | усе, що згенеровано і ще не апрувнуто: версії, тести, HTML-тюнери, скрипти | ні |
| `art/concept/` | концепти екранів після апруву | так |
| `art/objects/buildings/<назва>/` | будівлі після апруву | так |

Нові типи об'єктів (юніти, вороги, кристали, UI) — нова підпапка в `art/objects/` за тим самим
принципом: `art/objects/<тип>/<назва>/`.

## Іменування

- Латиниця, `snake_case`: `core`, `drill`, `relay`, `machine_gun`.
- Файли всередині папки з префіксом назви об'єкта (`drill_body.png`, не `body.png`): у пошуку Godot
  одразу видно, чий файл.
- Версії (`_v1`, `_v2`) — тільки в чернетках і концептах. В `objects/` лежить одна, фінальна.

## Процес: від промпту до апруву

1. **Промпт** — за шаблоном зі [стилем](#стиль-обовязково-в-кожному-промпті) нижче.
   Референси передаються картинками (`-i`): концепт екрана і вже апрувнуті спрайти.
2. **Генерація** — Codex, результат копіюється в `art/drafts/<тип>/<назва>_vN.png`.
3. **Самоперевірка** ([чекліст](#перевірки-перед-показом)). Не пройшла — правиться промпт і ще одна
   спроба. **Максимум 2 спроби** на ассет, далі показ людині як є, з описом проблем.
4. **Ревью людиною.** Правки → нова версія в чернетках.
5. **Апрув** → файл переноситься (`mv`) у робочу папку і перейменовується за правилами вище.
6. Разом з артом в його папку переноситься HTML-тюнер, якщо він був (див. вище).
7. Після апруву чернетки можна видаляти — людина чистить `art/drafts/` сама або просить про це.

Неапрувнуте ніколи не кладеться в робочі папки.

## Генерація через Codex

Codex CLI на підписці ChatGPT, вбудований інструмент `$imagegen` (gpt-image-2), без API-ключа.

```
codex exec -s read-only --skip-git-repo-check '$imagegen <промпт>. After generating, print only the absolute path of the saved PNG file.' -i <референс1.png> <референс2.png>
```

- Картинка зберігається в `~/.codex/generated_images/<session>/…png`; шлях — останній рядок виводу.
- `-i` **в кінці** команди: він приймає кілька файлів і «з'їдає» промпт, якщо стоїть перед ним.
- Команда — один рядок, без `cd … &&`, без `|`, без `< /dev/null`: інакше не спрацьовує виняток
  sandbox (`"codex exec *"` у `.claude/settings.json`) і Codex падає з `Operation not permitted`.
- Довгі генерації — у фоні; 3 паралельно працюють.
- Генерація картинок витрачає ліміти Codex у 3–5 разів швидше за звичайні запити.

## Стиль: обов'язково в кожному промпті

Англійською, бо так промпт іде в Codex:

```
2.5D top-down 3/4 view, camera tilted about 30 degrees; polished game art with a light hi-res
pixel-art feel (about 128 px per unit), NOT chunky retro 16-bit; crisp sharp edges, high contrast,
bright clean colors, no blur, no soft airbrush look.
LIGHT: one sun high on the upper right: right-facing surfaces lit, left-facing surfaces in shade.
NO light beams, NO glow halos, NO sparkles, NO particles baked into the sprite.
Transparent background, no ground texture.
```

Для концептів екранів додатково: палітра (фіолетова заражена земля проти блакитного радіуса бази,
сині кристали), HUD (темні заокруглені панелі з тонкою блакитною рамкою, золоті кнопки), текст UI
англійською, коротко. Референс стилю — `art/concept/01_mining_v1.png`.

### Чому саме так (з досвіду)

- Кожне перемалювання чи редагування в Codex робить картинку м'якшою («мильною») і пласкішою.
  Гарний спрайт краще правити **кодом** (маска, заміна ділянки), ніж генерувати знову.
- Ефекти в спрайті не можна анімувати — їх малює рушій (`Tween`, шейдери, частинки).
- Світлотінь на самому об'єкті кодом виглядає як фільтр — її малює Codex.

## Світло і тіні

| Що | Хто робить | Як |
|---|---|---|
| Світлотінь на об'єкті | Codex | сонце справа вгорі, у промпті |
| Тінь нерухомої будівлі на землі | Codex | малює разом зі спрайтом; потім відділяється в `<назва>_shadow.png` |
| Тінь рухомих частин | код | проекція по шарнірах (див. нижче), напрям узгоджений з тінню Codex |
| Тінь юнітів | код | тінь-еліпс під кожним (`concept.md`) |

**Як відділити тінь від спрайта:** тінь — це напівпрозорі темні пікселі (`alpha < 215` і
`r+g+b < 200`), решта — об'єкт. Під об'єктом тінь потрібно заповнити суцільно, інакше при зсуві
тіні лишається тільки контур.

**Напрям сонця для коду** береться з тіні Codex: на 1 px висоти точка зсувається на
`tx = -0.45` по X і `ty = +0.2` по Y (виміряно на корпусі бура).

## Будівлі з рухомими частинами

Приклад — бур (`art/objects/buildings/drill/`): корпус + рука з 3 сегментів.

1. Codex малює **зібраний** об'єкт (стиль, пропорції, шарніри видно чітко).
2. Codex перемальовує його **розібраним**: кожна частина окремо з прозорими проміжками,
   «той самий масштаб і поворот, лише рознесено». Заховані місця (кінці шарнірів) домальовуються.
3. Частини вирізаються заливкою по альфі. Злиплі частини розрізаються по шарніру; диск шарніра
   лишається верхній частині — тоді при обертанні на стику немає щілини.
4. Центри шарнірів знімаються по збільшеній сітці.
5. Збірка перевіряється в Python: зібрані частини мають дати картинку кроку 1.
6. HTML-тюнер з повзунками (пози, час, тінь) — людина налаштовує, значення йдуть у `<назва>_rig.json`.
7. Якщо Codex перемалював частину в іншому масштабі — підганяється по збігу силуету (IoU) зі старою.

Склад папки:

```
<назва>_body.png, <назва>_body_shadow.png   корпус і його тінь (Codex)
<назва>_arm_1.png … _N.png                  частини, усі в спільних координатах (ставити в 0,0)
<назва>_rig.json                            шарніри, порядок малювання, пози, час, тінь
<назва>_assembled.png                       зібране прев'ю з тінями
```

`<назва>_rig.json` (поля з `drill_rig.json`):

| Поле | Що |
|---|---|
| `shoulder_on_body` | точка кріплення першої частини на корпусі |
| `segN.pivot` / `end` (`tip`) | шарнір частини і її кінець, де кріпиться наступна |
| `draw_order` | порядок малювання знизу вгору |
| `pose_up`, `pose_drill` | кути в градусах, за годинниковою стрілкою, відносно зібраної пози |
| `timing_s`, `shake` | тривалість фаз і сила вібрації |
| `shoulder_ground` | точка на землі під кріпленням — для тіні |
| `arm_shadow` | модель і параметри тіні частин (`tx`, `ty`, товщина `k`, прозорість, розмиття, колір) |

У Godot: ланцюжок `Node2D` (корпус → суглоб 1 → суглоб 2 → суглоб 3), кожна частина обертається
навколо свого `pivot`; анімація — `Tween` між позами плюс синус для вібрації.

## Перевірки перед показом

- [ ] Об'єкт той, що просили; деталі відповідають концепту.
- [ ] Прозорий фон справжній: накласти на світлий колір (PIL) — без темного ореолу.
  `Read` показує прозорість чорним, на око не перевіряти.
- [ ] Немає запечених променів, ореолів, іскор.
- [ ] Світло справа вгорі, тінь вліво, будівля стоїть на землі (контактна тінь під краями).
- [ ] Не обрізано рамкою картинки (є прозорий відступ з усіх боків).
- [ ] Чіткість не гірша за еталон (`core.png`), не «мильно».
- [ ] HTML-тюнер перед показом прогнаний у Node з заглушками DOM/canvas на кілька сотень кадрів:
  `node --check` ловить тільки синтаксис.

## Чого не робити

- Не класти неапрувнуте в `concept/` чи `objects/`.
- Не перемальовувати в Codex те, що вже подобається, заради дрібної правки.
- Не запікати світлові ефекти в спрайт.
- Не малювати тінь окремою генерацією «тільки тінь» — вона не збігається з силуетом.

## Відкриті питання

- Кут камери: `concept.md` каже ~45°, по ядру виміряно ~30° (пропорції верхнього кільця ≈ 1:2).
  Промпти зараз — «about 30 degrees».
- Розмір спрайтів у грі: згенеровані 1536×1024, у Godot їх треба обрізати й зменшувати; цільовий
  розмір на юніт ще не вибрано.
