# Світло і тіні

Застосовувати, коли в задачі є тінь чи світлотінь.

## Хто що малює

| Що | Хто | Як |
|---|---|---|
| Світлотінь на самому об'єкті | Codex | сонце справа вгорі — стиль-блок промпту (SKILL.md, крок 4) |
| Тінь нерухомої будівлі на землі | Codex | разом зі спрайтом; потім відділити в `<назва>_shadow.png` (нижче) |
| Тінь рухомих частин | код | проекція по шарнірах, напрям як у тіні Codex |
| Тінь юніта | код | тінь-еліпс під кожним |

Світлотінь на об'єкті кодом не малювати — виглядає як фільтр.
Окрему генерацію «тільки тінь» не робити — вона не збігається з силуетом.

## Відділити тінь від спрайта будівлі

1. Тінь = напівпрозорі темні пікселі: `alpha < 215` і `r+g+b < 200`. Решта — об'єкт.
2. Під об'єктом тінь заповнити суцільно, інакше при зсуві тіні лишається тільки контур.
3. Результат як в `art/objects/buildings/core/`: `core_shadow.png`, `core_shadow_cast.png`,
   `core_shadow_contact.png`, `core_with_shadow.png`.

## Напрям сонця для коду

Брати з тіні Codex. Виміряно на корпусі бура: на 1 px висоти точка тіні зсувається на `tx = −0.45` по X і
`ty = +0.2` по Y. У коді бура інакше: `drill_rig.tres` ці поля не задає, тому діють значення за замовчуванням
з `game/objects/drill/drill_rig.gd` — `shadow_tx = −0.3`, `shadow_ty = 0.2`. Чому −0.3, а не −0.45, — не знаю.
Для нового об'єкта спитати людину, яке значення брати.
