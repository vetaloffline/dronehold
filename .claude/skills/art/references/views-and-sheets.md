# Ракурси, аркуші й нарізка

Застосовувати, коли об'єкт чи його частина повертається (турель, дрон, тарілка) або коли Codex віддає
кілька кадрів одним аркушем.

## Загальне

- Плаский спрайт не крутити `rotation` і не доповертати спрайт ракурсу на екрані: у 2.5D корпус хилиться з
  основи. Замість цього — набір ракурсів, що перемикаються ривками за кутом (режим `snap`).
- Азимут на землі: 0° = вправо, 90° = до камери.
- Кожен ракурс → точка кріплення `housing` і дуло `muzzle` у пікселях PNG; поля в
  `game/objects/turret/turret_rig.gd` (`housing`, `muzzle`, `view_azimuths`), значення — у
  `<назва>_rig.tres`. Звідти вилітають трасер і спалах.

## Турелі: 16 ракурсів

1. 8 ракурсів можна одним аркушем 3×3 (основа в центрі + 8 голів навколо, крок 45°): аркуш тримає єдиний
   дизайн, але не тримає точні кути.
2. 16 ракурсів → одна голова на генерацію:
   - шаблон пози: блокова 3D-коробка корпусу + ствол рівно в потрібний азимут, стиск камери 0.75;
   - + 2 сусідні апрувнуті голови як зразок дизайну.
   «Намалюй посередині між сусідами» не працює: Codex малює копію сусіда (202,5° вийшло як 225°).
3. Мортира (задерта труба) → ще стрілка-компас на землі. Ракурси «до камери» Codex недокручує навіть з
   шаблоном → заміряти й показати похибку людині.
4. Підгонка й заміри — `art/objects/buildings/turret_views_fit.py`: масштаб за площею сусідів; кріплення =
   центр корпусу + поправка, вивчена на апрувнутих (`--check`); дуло = крайня точка по осі ствола.
   Заміряний азимут кожного кадру кулемета записати в `view_azimuths`; у гранатомета азимути рівномірні.

## Дрон: 8 ракурсів

`art/objects/units/drone/`:
1. Шаблон `drone_views_template.py`: блоки, повернуті на 0…315°, червоний ніс = перед, K = 0.75.
2. Аркуш 3×3 від Codex → нарізка `drone_views_cut.py` → підгонка `drone_views_fit_one.py`.
3. Полотно 321×295, центр = середина дрона. Журнал — `prompts.md` там же.
4. Перемальований окремо ракурс → масштаб під ширину старих сусідів, центр = центроїд альфи.

## Рухома частина на статичному корпусі (тарілка ретранслятора)

1. Корпус → один статичний спрайт: основа + щогла + шпиль/вісь зверху (не зріз), на який сідає частина.
   Корпус апрувиться окремо.
2. Рухома частина → генерується сама, без корпусу: тарілка + кронштейн + втулка знизу.
3. Шаблон → 3D-модель частини, що обертається навколо вертикальної осі втулки: втулка = `housing` в одній
   точці кадру в усіх 16 ракурсах; кронштейн видно і він суцільний у кожному ракурсі; аркуш шаблонів →
   людині до генерації.
4. Розмір → до 3D-моделі одним множником на весь спрайт (зум Codex заміряний проти моделі); частини окремо
   не масштабувати. Кут ±5° і посадку на шпиль міряти окремо.
5. Скрипти в `art/objects/buildings/relay/`: `dish_v2_template.py` (3D-модель, шаблони, аркуш для людини,
   перевірка «один шматок + шарнір на housing»), `dish_v2_color.py` (кольоровий рендер для Codex),
   `dish_v2_measure.py` (кут, зум, зсув, IoU, контакт шарніра), `dish_v2_place.py` (повернення до розміру
   моделі, аркуш на шпилі).

Чому так (спроба 1, 2026-10-12, провал): шаблон крутив тарілку не навколо осі щогли, кронштейн у задніх
ракурсах не з'єднував тарілку з кільцем → тарілка висіла в повітрі; кожен ракурс масштабувався окремо
(`frame_scale` 0,40…0,57) → тарілка «дихала»; ракурс з похибкою +13,5° потрапив у «найкращі» замість звіту.

## Нарізка аркуша

1. Різати по сітці клітинок. З кожної клітинки лишати тільки найбільшу зв'язну компоненту (інакше по краях
   лишаються уламки сусідніх ракурсів).
2. Білий фон: фон = майже білі пікселі (`min(r,g,b) >= 232`), зв'язані з краєм клітинки (заливка від краю);
   смуга 2–3 px по краю → colour-to-alpha проти білого; всередині — непрозоро. Готове — `drone_views_cut.py`.
3. Усі кадри → на одне полотно однакового розміру з однією точкою опори (інакше в грі кадри «стрибають»).
